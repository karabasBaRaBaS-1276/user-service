# user-service

## Описание

`user-service` — бэкенд‑сервис управления пользователями и их аутентификацией, реализованный на Go.

Сервис отвечает за:

* учет пользователей системы;
* хранение и управление персональными данными пользователя;
* хранение учетных данных (логин / пароль в зашифрованном виде);
* аутентификацию пользователей и выдачу JWT‑токенов доступа;
* предоставление HTTP API для работы с пользователями.

Сервис предназначен для использования как самостоятельный backend‑компонент и может быть частью монолитного приложения или модульного монолита.

---

## Функциональные возможности

* CRUD‑операции над пользователями
* Аутентификация по логину и паролю
* Выдача JWT access‑token
* Валидация входных данных
* Явное разделение:

  * доменной логики
  * транспортного слоя (HTTP)
  * работы с хранилищем

---

## Архитектура

Проект построен с опорой на идиоматичные практики Go:

* код — основной источник истины;
* HTTP рассматривается как транспорт;
* бизнес‑логика изолирована от деталей хранения и доставки;
* зависимости направлены извне внутрь.

Высокоуровневая структура:

```
user-service/
  ├── api/                    // OpenAPI контракт (временный)
  ├── cmd/                    // точки входа (main)
  ├── docs/                   // документация mkdocs
  ├── internal/
  │   ├── app/                // сборка и запуск приложения
  │   ├── auth/               // аутентификация и токены
  │   ├── user/               // домен пользователей
  │   ├── transport/http/     // HTTP handlers, router, middleware
  │   ├── service/            // бизнес-логика (use cases).
  │   ├── repository/         // работа с хранилищем
  │   └── domain/             // чистые структуры и бизнес-типы
  ├── pkg/                    // для пакетов, которые могут использоваться извне
  ├── migrations/             // миграции для БД
  ├── go.mod
  └── README.md
```

## API и OpenAPI

В проекте используется OpenAPI для описания HTTP API.

На текущем этапе:

* спецификация `api/openapi.yaml` поддерживается вручную;
* файл используется как временный контракт.

Планируемый переход:

* OpenAPI будет генерироваться автоматически из Go‑кода на основе аннотаций HTTP‑обработчиков;
* ручная спецификация будет удалена после завершения миграции.

---

## Аутентификация

Сервис реализует базовую аутентификацию пользователей:

* проверка учетных данных (логин / пароль);
* генерация JWT access‑token;
* использование токена для доступа к защищённым эндпоинтам.

JWT и механизмы аутентификации не проникают в доменную модель пользователя и рассматриваются как деталь реализации транспортного слоя.
